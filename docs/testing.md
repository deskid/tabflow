# TabFlow 功能验证指南

适用版本：1.1.0。此指南用于验证浏览器中的实际功能；自动化检查命令与安装步骤见 [README](../README.md)，数据处理边界见 [隐私与数据说明](../PRIVACY.md)。

## 环境与准备

使用桌面 Chrome 120 或更新版本；Chrome 端侧模型另受当前 Chrome API、硬件、磁盘、网络和语言支持限制。Windows 本机 Codex 为可选功能，其他系统没有配套安装器。

按 README 构建并加载扩展。建议使用独立测试浏览器资料和公开示例页面，避免关闭或修改私人标签与书签。基础功能无需 Codex 登录或 API Key；验证可选服务时使用自己有权访问的接口和账号，不要在日志、截图或问题反馈中附带密钥和敏感网址。

## 1. 基础管理与本地规则

1. 在一个普通浏览器窗口打开几页公开页面，如两个 GitHub 页面、两个 MDN 文档页面和一个公共资讯页面。可先在偏好设置关闭「新标签自动归类」，方便对比手动整理结果。
2. 点击工具栏 TabFlow 图标，或用 Ctrl+Shift+P（macOS 为 Command+Shift+P，若系统无冲突）打开侧边栏。
3. 检查垂直标签列表、标题搜索、切换、固定、取消固定和静音操作；关闭操作仅用临时测试页。检查界面跟随原生标签变化刷新。
4. 新安装的分类引擎应为「本地规则」。已有安装保留旧引擎，验证时可手动选择「本地规则」。此路径无需桥接、下载模型或填写密钥。
5. 点击「智能分组」，使用标题／网址关键词及域名规则整理。有足够匹配页面时产生原生标签组；没有匹配标签时不保证创建组。结果应说明实际使用本地规则。
6. 修改原生组名、颜色并折叠／展开，检查 Chrome 与 TabFlow 的同步；也可触发按域名整理。
7. 在书签页搜索并打开测试书签，将测试标签组保存为书签，再删除测试项。稍后读页测试添加页面、切换已读和删除；也可用页面右键菜单添加稍后读。
8. 开启新标签自动归类，再打开同域名公开页面，观察归组；关闭开关后重复，确认不会继续自动整理。该能力按本地规则运行，不调用模型。

## 2. 分组风格与设置同步

进入偏好设置，逐一选择「主题聚合」「项目任务」「使用场景」「资料类型」「站点服务」「极简收纳」，检查提示词随预设变化；编辑后应显示自定义状态，也可恢复默认。切换侧边栏、独立窗口和选项页，或重新打开设置，检查设置同步与保留。

预设是模型提示词，不能用本地规则分类的实际组名判断模型遵循度。未配置模型时可测试选择、编辑和保存；端侧或 API 可用时，再比较模型整理结果。模型输出具有差异，不保证每次同名、同数分组。各引擎独立保留模型、密钥和地址，切换引擎后检查恢复原配置；分组偏好全局共用。

## 3. 撤销与失败处理

1. 创建有名称、颜色和折叠状态的测试组，另留未分组页面，记下标签顺序。
2. 触发规则或模型分组，产生实际新组后，在约 8 秒的「撤销」提示有效期内点击撤销。
3. 检查可恢复标签的分组、组名、颜色、折叠状态和顺序。已被 Chrome 删除的空组可能以新组 ID 重建；撤销不是关闭标签恢复功能。
4. 整理后关闭测试标签或移到别的窗口，再撤销；这些标签应被跳过。撤销失败时保留重试入口。
5. 可选模型缺失或 API 请求失败时，界面应显示失败原因和实际按域名处理结果。有同域名标签时可能创建组，没有时显示未调整；结果应区分模型失败与规则处理。取消端侧任务或等待预检不会执行部分分组或域名兜底。

## 4. 独立窗口绑定

从普通窗口 A 打开独立 TabFlow 窗口（界面入口或 Ctrl+Shift+E／Command+Shift+E）。另开普通窗口 B 并切换焦点。独立窗口仍管理 A，新建标签、打开书签及稍后读应落在 A；关闭 A 后显示来源窗口不可用并停止标签操作。

## 5. Chrome 端侧模型（可选）

选择「Chrome 端侧模型」，先看只读可用性检测。仅打开设置不会下载模型。可用时显式点击下载或智能分组；预检刚完成时可能需再点击一次以保留下载所需的用户手势。观察下载进度、取消和状态。

资源下载后还会创建会话并运行不含标签的英文自检，成功才显示就绪。支持的环境可用少量公开英文页面测试分类，检查进度及英文组名。准备模型会联网，推理在设备上执行。中文输入可能因模型语言支持失败；设备缺乏支持条件时显示不可用或具体错误属于预期。

每批最多 12 个标签，汇总为最多 6 组，每批结束后释放会话。仅遗漏少量标签时补问一次，仍无可靠分类的标签放入 `Other` 并明确提示数量；完全无结果、未知／重复 ID 或无效结构会整批报错。检查进度、取消与实际分组结果，取消不应执行部分结果。

## 6. OpenAI、DeepSeek 与自定义 API（可选）

设置中选择对应引擎，填写接口、所需密钥和模型。自定义服务不要求密钥时可留空。首次连接自定义主机时，点击模型旁「连接」并授予所选协议与主机的访问权限；Chrome 权限覆盖同主机该协议下的所有端口和路径。授权后可读取模型目录，也可手动填写模型 ID。读取目录发送配置的 API Key，不发送标签内容；目录可用不保证模型有推理权限或额度。

自定义兼容服务可提供 `GET /models` 与 `POST /chat/completions` 接口，分类响应按请求要求返回包含组名、颜色与标签 ID 的 JSON。使用公开页面执行智能分组，核对发送标签 ID、标题、完整网址及提示词的行为。错误地址、拒绝授权、无效密钥或无效模型应显示真实错误。远程接口优先选择 HTTPS；自定义接口也允许 HTTP，HTTP 没有传输加密。

## 7. Windows 本机 Codex（可选）

基础管理不依赖此路径。官方 Codex CLI 及 Native Messaging Host 需要独立安装，不包含在扩展 ZIP 内。先安装 Node.js、官方 Codex CLI，并在当前 Windows 用户下完成 `codex login` 或所需提供商配置。

在 `chrome://extensions/` 开启开发者模式并复制目标 TabFlow 的 ID，再在完整项目根目录运行：

```powershell
$extensionId = Read-Host '粘贴 chrome://extensions/ 中目标 TabFlow 的 ID'
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-native-host.ps1 -ExtensionId $extensionId -WhatIf
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-native-host.ps1 -ExtensionId $extensionId
```

预演需要有效 Node.js、Codex CLI 及可选 CodexHome 路径，不写文件或注册表。实际安装为当前用户注册 `com.tabflow.codex_bridge`。不同构建或安装方式可能有不同 ID；检查生成的 host 清单 `allowed_origins` 是否允许目标 `chrome-extension://<扩展ID>/`。省略 `-ExtensionId` 时按开发清单公钥推导 ID。安装器每次注册一个允许来源，重新绑定会替换旧 ID。

重新加载扩展，在偏好设置选择「本机 Codex」并刷新。预期显示真实认证状态、模型目录或可解释错误；未安装 host 时显示未连接，基础管理和本地规则仍可用。模型目录不保证每个模型都有调用额度。使用公开页面测试分类；模型由 CLI 当前配置决定，可能在云端推理。扩展不接收 CLI 登录令牌或账号邮箱。

## 8. 数据与代码边界

设置、各引擎配置、API Key 与提示词保存在 `chrome.storage.sync`，可能随 Chrome 同步到账号关联设备；切换引擎不会删除旧密钥。云端和 Codex 分类使用完整网址，包括查询参数和片段，当前不会自动脱敏。验证完毕后，可逐个清空测试密钥与配置，按需撤销站点权限，并清理测试标签、书签和稍后读。

扩展没有正文抓取内容脚本、远程 JS 或模型输出 eval；输出由包内逻辑应用为分组操作。本机 host 单独安装，行为源码可审阅。云端响应尚未统一采用端侧模型及 native 桥接的完整标签 ID 校验；相关实现边界见 [README](../README.md)，完整数据流与删除说明见 [隐私与数据说明](../PRIVACY.md)。
