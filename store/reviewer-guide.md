# TabFlow 1.1.0 审核测试说明

以下为开发者后台审核说明草稿。基础路径不需要审核员提供私人账号、API Key 或 Codex 登录。可选功能若审核必须验证受保护接口，发布者应通过后台的非公开测试说明提供专用、限额、可撤销测试访问；当前没有附带真实 token，也没有声称已提供可用测试账号。用户已创建商店条目，实际扩展 ID 为 `pnjgkehmcfheoecnhenfeidkpkdjifkm`；条目尚未公开。提交前仍需补齐审核所需的访问方式。

## 用途与环境

TabFlow 的单一用途是整理浏览会话。扩展在侧边栏和独立窗口管理标签、原生标签组、书签与稍后读，并提供规则或可选模型分类。

使用桌面 Chrome 120 或更新版本；Chrome 端侧模型另受当前 Chrome API、硬件、磁盘、网络和语言支持限制。Windows 本机 Codex 为可选高级功能，其他系统没有配套安装器。基础测试建议在独立测试浏览器资料中进行，避免关闭或修改私人标签与书签。

## 1. 无凭据基础路径

1. 安装上传的 1.1.0 包，在一个普通浏览器窗口打开几页公开示例页面，如两个 GitHub 页面、两个 MDN 文档页面和一个公共资讯页面。可先在偏好设置关闭「新标签自动归类」，方便对比手动整理结果。
2. 点击工具栏 TabFlow 图标；或用 Ctrl+Shift+P（macOS 为 Command+Shift+P，若系统无冲突）打开侧边栏。
3. 检查垂直标签列表、标题搜索、切换、固定、取消固定和静音操作；关闭操作仅用临时测试页。检查界面跟随原生标签变化刷新。
4. 新安装的分类引擎应为「本地规则」。已有安装会保留旧引擎；如不是全新测试资料，先手动选择「本地规则」。无需桥接、下载模型或填写密钥。
5. 点击「智能分组」，使用标题／网址关键词及域名规则整理；有足够匹配页面时产生原生标签组。没有匹配标签时不保证创建组。结果应说明实际使用本地规则，不应显示为模型成功。
6. 修改原生组名、颜色并折叠／展开，检查 Chrome 与 TabFlow 的同步。也可触发按域名整理。
7. 在书签页搜索并打开测试书签，将测试标签组保存为书签，再删除测试项。稍后读页测试添加页面、切换已读和删除；也可用页面右键菜单添加稍后读。
8. 开启新标签自动归类，再打开同域名公开页面，观察归组；关闭开关后重复，确认不会继续自动整理。该能力按本地规则运行，不调用模型。

## 2. 六种分组风格

进入偏好设置，逐一选择「主题聚合」「项目任务」「使用场景」「资料类型」「站点服务」「极简收纳」，检查提示词随预设变化；编辑后应显示自定义状态，也可恢复默认。切换界面或重新打开设置，检查设置保留。

预设是模型提示词，不能用默认本地规则分类的实际组名来断言模型遵循度。无凭据时可完整测试选择、编辑和保存；端侧或专用测试 API 可用时，再比较各风格的模型整理结果。模型输出具有差异，不保证每次同名、同数分组。

## 3. 撤销与失败处理

1. 创建有名称、颜色和折叠状态的测试组，另留未分组页面；记下标签顺序。
2. 触发规则或模型分组，产生实际新组后，在约 8 秒的「撤销」提示有效期内点击撤销。
3. 检查可恢复标签的分组、组名、颜色、折叠状态和顺序；已被 Chrome 删除的空组可能以新组 ID 重建。撤销不是关闭标签恢复功能。
4. 整理后关闭测试标签或移到别的窗口，再撤销；这些标签应被跳过。撤销失败时保留重试入口。
5. 可选模型缺失或 API 请求失败时，界面应显示失败原因和实际按域名处理结果；有同域名标签时可能创建组，没有时显示未调整。不要把此结果当作模型调用成功。取消端侧任务或等待预检不会执行部分分组或域名兜底。

## 4. 独立窗口绑定

从普通窗口 A 打开独立 TabFlow 窗口（界面入口或 Ctrl+Shift+E／Command+Shift+E）。另开普通窗口 B 并切换焦点。独立窗口仍管理 A，新建标签、打开书签及稍后读应落在 A；关闭 A 后显示来源窗口不可用并停止标签操作。

## 5. Chrome 端侧模型（可选，无服务密钥）

选择「Chrome 端侧模型」，先看只读可用性检测。仅打开设置不会下载模型。可用时显式点击下载或智能分组；预检刚完成时可能需再点击一次以保留下载用户手势。观察下载进度、取消和状态。

资源下载后还会创建会话并运行不含标签的英文自检，成功才显示就绪。支持的环境可用少量公开英文页面测试分类，检查进度及英文组名。准备模型会联网，推理在设备上执行。中文输入可能因模型语言支持失败；无支持条件的设备显示不可用／具体错误属于预期，不应要求审核员修改设备或提交私人数据。端侧能力不是全设备承诺。

## 6. OpenAI、DeepSeek 与自定义 API（可选）

设置中选择对应引擎，填写接口、所需密钥和模型。点击模型旁「连接」／刷新，请求所选协议与主机的站点访问权；Chrome 权限覆盖同主机该协议的所有端口。授权后可读模型目录，也可手动填写模型 ID。目录读取发送配置的 API Key，不发送标签；目录可用不保证所有模型有推理权限或额度。

端到端分类需要发布者提供的测试服务（若审核要求），不要求审核员提供私人密钥。测试服务应支持兼容的 GET models 目录和 POST chat/completions，并按返回 JSON 提供组名、颜色与标签 ID。可使用发布者提供的无认证测试接口或专用可撤销测试凭据；提交前应在非公开测试说明中填写实际地址、模型、有效期及撤销安排，不能把占位文字当作可用服务。

选择公开测试页执行智能分组，核对发送标签 ID、标题、完整网址及提示词的行为。错误地址、拒绝授权、无效密钥或无效模型应显示真实错误；HTTPS 远程接口优先。产品也接受自定义 HTTP，不能将这条路径描述为全部加密。请勿使用私人 URL 或敏感提示词验证。

## 7. Windows 本机 Codex（可选，外部安装）

基础管理不依赖此路径。仓库提供 Windows PowerShell 安装脚本；官方 Codex CLI 及 Native Messaging Host 需要独立安装，不包含在商店扩展 ZIP 内。

已知实际商店扩展 ID 为 `pnjgkehmcfheoecnhenfeidkpkdjifkm`。提交前仍需核对安装器 `-ExtensionId` 参数及实际注册结果。商店包不含开发用 manifest.key；不得使用源码公钥算出的本地扩展 ID 代替商店 ID。Native Messaging 的 allowed_origins 必须允许 `chrome-extension://pnjgkehmcfheoecnhenfeidkpkdjifkm/`。

具备专用测试 Windows 环境时，先安装 Node.js、官方 Codex CLI，完成 CLI 所需的测试认证或提供商配置，再使用仓库安装器注册当前用户的 host `com.tabflow.codex_bridge`：

```powershell
# 在完整项目目录运行；使用已创建条目的实际商店扩展 ID
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-native-host.ps1 -ExtensionId pnjgkehmcfheoecnhenfeidkpkdjifkm
```

命令已填实际商店 ID，但尚不代表已执行或验证本机注册；执行及验证仍是提交前核对项。安装器及源码位置：https://github.com/deskid/tabflow/tree/main/scripts （1.1.0 更新已推送至公开 main 分支）。重新打开扩展，在偏好设置选择「本机 Codex」并刷新。预期显示真实认证状态、模型目录或可解释错误；未安装 host 时显示未连接，但基础管理及本地规则仍可用。

模型目录不保证每个模型都有调用额度。使用公开页面测试分类，模型由 CLI 当前配置决定，可能在云端推理；扩展不接收 CLI 登录令牌或账号邮箱。若此路径审核需要受保护功能，发布者应提供专用可撤销测试访问／与审核方确认可接受的测试安排，不要求审核员使用私人 Codex 账号。
